# Build Order — AI Engineering Layers Projects

Sequenced per the source doc's own logic: layers are cumulative (don't skip ahead), the bottleneck moves outward one layer at a time, and within a layer you build the simplest/foundational thing before the safety-critical or most complex thing.

## Phase 1 — Prompt Engineering (quick wins, no infra needed)
1. **Email Classification Service** — simplest possible task, single classification call
2. **Meeting Notes Summarizer** — structured extraction from unstructured input
3. **Code Review Chatbot** — multi-criteria reasoning over code
4. **Simple RAG Chatbot** — introduces retrieval, bridges into Context Engineering

## Phase 2 — Context Engineering (retrieval + grounding)
5. **Product Documentation Assistant** — natural extension of the RAG chatbot, adds citations
6. **Internal Data Analyst for Business Intelligence** — adds schema + metric-definition grounding
7. **Codebase-Aware Pair Programmer** — heavier indexing (codebase, commits, architecture)
8. **Multi-Repo Code Generation** — builds directly on the pair programmer, extends across repos

## Phase 3 — Harness Engineering (reliability, guardrails, autonomy)
9. **Enhanced Multi-Agent Stock Analyzer** — you already have this; strengthen it first (guardrails + observability) before starting anything new — matches the doc's own Phase 1 recommendation
10. **Autonomous Bug Triage Agent** — first new harness build; moderate stakes, good place to practice tool orchestration + guardrails
11. **Self-Healing Documentation Generator** — adds approval gates and confidence thresholds
12. **GCP Infrastructure Provisioner** — highest stakes (production infra, cost, security) — do last in this layer, once guardrail patterns are proven

## Phase 4 — Loop Engineering (iteration until "done")
13. **Autonomous Code Review and Merge** — the doc explicitly names this as the first loop-engineering project to build
14. **Data Pipeline Debugger** — the doc's other suggested starting point; clean stop condition (fix resolves error)
15. **Report Generation with Validation** — schema-based verification, slightly more surface area
16. **Recursive Problem Solver** — most open-ended (decomposition + adaptive re-planning) — do last

## Phase 5 — Graph Engineering (multi-agent coordination)
17. **Customer Support Triage and Resolution** — simplest graph shape (one router, a few parallel specialists)
18. **Research Paper Writing Factory** — mostly linear pipeline with one feedback loop, good second graph
19. **Internal Audit and Monitoring Platform** — continuous/event-driven graph, more moving parts
20. **Autonomous Trading Hedge Fund** — high-stakes, many agents, compliance-critical — build once graph patterns are solid
21. **AI Services Company Operations** — most complex, ties together everything upstream (client-facing, financial, multi-phase) — the capstone

## Rationale (from the source doc)
- "Each layer builds on previous... the stack is cumulative"
- "Start simple. Add layers only when the current layer fails."
- Within Harness/Loop/Graph, safety-critical or highest-complexity projects are sequenced last, after guardrail and coordination patterns are proven on lower-stakes work.
